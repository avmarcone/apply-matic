# Implementation Plan: Greenhouse Form Filler

**Branch**: `003-answer-generator` | **Date**: 2026-05-19 | **Spec**: [spec.md](spec.md)

**Input**: Feature specification from `specs/002-greenhouse-form-filler/spec.md`

## Summary

Implement a Playwright-based form filler that opens a Greenhouse job application URL
in a headed Chromium browser, detects and fills all **required** standard fields (first
name, last name, email, phone, resume) using a five-strategy detection cascade, collects
open-ended narrative questions for AI answering, and pauses for human review before any
further action. Optional fields are intentionally left untouched.

## Technical Context

**Language/Version**: TypeScript 5.x (strict mode)

**Primary Dependencies**: Playwright (Chromium), `@anthropic-ai/sdk`, `csv-parse`, `dotenv`

**Storage**: `jobs.csv` (status updates), `profile.json` (read-only source of field values)

**Testing**: Vitest — unit tests for field detection logic, selector cascade, and open-ended
question classification; Playwright tests for integration (requires headed browser)

**Target Platform**: macOS/Linux (headed display required — constitution Principle V)

**Project Type**: CLI tool (Node.js)

**Performance Goals**: Standard field filling phase completes in under 30 seconds per job

**Constraints**: No auto-submission under any circumstances (constitution Principle V);
required fields only — optional fields must not be touched

**Scale/Scope**: Single Greenhouse ATS platform, single user profile, v1 MVP

## Implementation Phases

### Phase 1: Required-Field Detection

Implement `requiredChecker.ts` — given a Playwright `Locator`, determines if the
associated form field is required via:
1. HTML `required` attribute present on the element
2. Associated `<label>` text contains `*`
3. Element or wrapper has a required CSS class (`required`, `field--required`)

Unit-testable by injecting mock HTML fragments via Playwright's `page.setContent`.

### Phase 2: Five-Strategy Field Detection Cascade

Implement `fieldDetector.ts` — given a page and a field definition (name, aria keywords,
label patterns, placeholder patterns, CSS selectors), tries each strategy in order and
returns the first matching `Locator`. Returns `null` if all strategies fail.

Field definitions for required standard fields (see research.md for full selector lists):
- `firstName`, `lastName`, `email`, `phone`, `resume`

Each field definition specifies required-field patterns; the cascade only proceeds if
`requiredChecker` confirms the located element is required.

### Phase 3: Form Fill Orchestration

Implement `fillForm.ts` using `fieldDetector` and `requiredChecker`:

1. Launch headed Chromium (`{ headless: false }`)
2. Navigate to `job.url`; wait for `networkidle`
3. For each required standard field:
   - Run 5-strategy cascade
   - If found and required: fill from `profile`
   - If not found: append to `skippedFields`
4. Upload resume via `page.locator(...).setInputFiles(profile.resumeFilePath)`
5. Scrape job description (selectors: `#content`, `.job-description`, `[data-job-description]`)
6. Run `questionCollector` to gather open-ended questions
7. Return `FillResult`

### Phase 4: Open-Ended Question Collection

Implement `questionCollector.ts`:

1. Find all `<textarea>` and `<input type="text">` elements on the page
2. For each, resolve the associated label text
3. Exclude any whose label matches a standard field pattern (see research.md)
4. Return remaining as `OpenEndedQuestion[]` with `questionText`, `fieldSelector`, `context`
