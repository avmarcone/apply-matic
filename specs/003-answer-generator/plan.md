# Implementation Plan: Answer Generator

**Branch**: `003-answer-generator` | **Date**: 2026-05-19 | **Spec**: [spec.md](spec.md)

**Input**: Feature specification from `specs/003-answer-generator/spec.md`

## Summary

Implement an AI-powered answer generator that accepts open-ended narrative questions
from the form filler (spec 002), filters out demographic/EEO questions without AI
calls, and generates 2–4 sentence contextual answers using a pluggable AI provider
(Claude API in production, Ollama locally). Answers are injected into the live
Playwright page; skipped demographic questions are surfaced for manual review.

## Technical Context

**Language/Version**: TypeScript 5.x (strict mode)

**Primary Dependencies**: `@anthropic-ai/sdk` (Claude provider), native `fetch`
(Ollama HTTP calls), Playwright (answer injection into live page)

**Storage**: None — reads from `profile.json` (spec 001), writes nothing

**Testing**: Vitest — unit tests for demographic filter, provider factory, and prompt
builder; integration test stubs via mock `AIProvider` implementation

**Target Platform**: macOS/Linux (same machine as spec 001/002)

**Project Type**: CLI tool module (Node.js)

**Performance Goals**: Each answer generated and returned within 10 seconds (cloud);
Ollama response time varies by local hardware

**Constraints**: Zero AI calls for demographic questions; no silent fallback from Ollama
to Claude; prompt caching applied when using Claude provider

**Scale/Scope**: 2–5 open-ended questions per application; single-user; v1 MVP

## Implementation Phases

### Phase 1: Types and Provider Interface

Define `AIProvider` interface, `AnswerResult`, and `InjectionSummary` in `src/answer/types.ts`.

**AIProvider interface**:
```typescript
interface AIProvider {
  generate(systemPrompt: string, userMessages: string[]): Promise<string>
}
```

### Phase 2: Provider Implementations

**ClaudeProvider** (`claudeProvider.ts`):
- Wraps `@anthropic-ai/sdk`
- Uses `claude-sonnet-4-6` (configurable via `CLAUDE_MODEL` env var)
- Applies `cache_control: { type: "ephemeral" }` to system prompt and resume block

**OllamaProvider** (`ollamaProvider.ts`):
- HTTP POST to `http://localhost:{OLLAMA_PORT}/api/generate` via native `fetch`
- Model from `OLLAMA_MODEL` env var
- Port from `OLLAMA_PORT` env var (default `11434`)
- On connection refused: throws clear error (no silent fallback)

**Factory** (`aiProvider.ts`):
- Reads `AI_PROVIDER` env var (`'claude'` default or `'ollama'`)
- Returns appropriate provider instance
- Validates connectivity for Ollama before returning

### Phase 3: Demographic Filter

Implement `isDemographic(questionText: string): boolean` in `demographicFilter.ts`.

- Case-insensitive substring match against keyword list (research.md Decision 6)
- Pure string matching — no external dependencies, fully unit-testable

### Phase 4: Answer Generation

Implement `generateAnswer(question, resumeText, provider)` in `generateAnswer.ts`:

1. `isDemographic(question.questionText)` → if true, return `{ status: 'skipped', skipReason: 'demographic' }`
2. Build system prompt + user messages (research.md Decision 4)
3. `provider.generate(systemPrompt, userMessages)`
4. Success → `{ status: 'answered', answer }`
5. Error → `{ status: 'failed', error }`

### Phase 5: Injection Orchestration

Implement `injectAnswers(page, questions, resumeText, provider)` in `injectAnswers.ts`:

- Calls `generateAnswer` for each question sequentially
- `answered`: `page.locator(fieldSelector).fill(answer)` + terminal log
- `skipped`: terminal log "⚠ skipped (demographic) — review manually"
- `failed`: stderr log + continue
- Returns `InjectionSummary`

No constitution violations. Provider abstraction is the minimum needed to support
