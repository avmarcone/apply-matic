# Implementation Plan: Job Queue Runner

**Branch**: `001-job-queue-runner` | **Date**: 2026-05-18 | **Spec**: [spec.md](spec.md)

**Input**: Feature specification from `specs/001-job-queue-runner/spec.md`

## Summary

Build the CLI orchestration layer for apply-matic. The tool reads `jobs.csv`, loads and
validates `profile.json`, processes each `pending` job sequentially by delegating to the
form filler and answer generator, then writes the result status (`applied` or
`review-needed`) back to `jobs.csv` after a human review prompt.

## Technical Context

**Language/Version**: TypeScript 6 / Node.js 22+

**Primary Dependencies**:
- `csv-parse` — CSV reading (already installed)
- `csv-stringify` — CSV write-back (to install)
- `dotenv` — environment config (already installed)
- `zod` — profile.json schema validation (to install)
- `readline` — built-in Node.js; terminal review prompt (no install)

**Dev Dependencies**:
- `vitest` — unit test runner (to install)
- `@vitest/coverage-v8` — coverage reporting (to install)

**Storage**: Flat files — `jobs.csv` (queue) and `profile.json` (user data)

**Testing**: Vitest — native TypeScript, no transform config needed

**Target Platform**: macOS local CLI (single-user, single machine)

**Project Type**: CLI tool

**Performance Goals**: Tool starts and reaches first job within 3 seconds (SC-005)

**Constraints**: Sequential processing only — no parallel browser sessions in v1

**Scale/Scope**: Single user; queue of up to ~100 jobs per run
